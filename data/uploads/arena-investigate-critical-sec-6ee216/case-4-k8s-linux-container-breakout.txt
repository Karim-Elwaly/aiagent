Executive Summary

A single Kubernetes worker node (k8s-worker-node-01) was compromised through a container breakout that enabled host‑level access, kernel rootkit installation, cluster‑admin privilege escalation, credential dumping, and persistence via a reverse‑shell cron job. The attacker leveraged the compromised service account webapp-sa to gain unrestricted control of the Kubernetes control plane and to exfiltrate secrets. Immediate isolation, kernel integrity verification, RBAC rollback, secret rotation, and crontab cleanup are required to contain the threat and prevent lateral movement.

5. Immediate Containment Actions
Quarantine Node
# On the compromised node
iptables -A INPUT -j DROP
iptables -A OUTPUT -j DROP

Kernel Integrity Verification & Module Removal
lsmod | grep diamorphine
rmmod diamorphine

Revoke Elevated Privileges
kubectl delete clusterrolebinding system-cluster-admin-binding

Secret Rotation
# Rotate all secrets in the default namespace
kubectl get secret -n default -o name | xargs -I{} kubectl delete secret {}

Cron & Persistence Cleanup
crontab -u www-data -l | grep -v '198.51.100.77' | crontab -
crontab -u deploy -l | grep -v '198.51.100.77' | crontab -

Auditd Logging Enhancement
echo "auditctl -a always,exit -F arch=b64 -S insmod,finit_module -k kernel_module_load" >> /etc/audit/rules.d/99-kernel.rules
echo "auditctl -a always,exit -F arch=b64 -S openat -F path=/etc/shadow -k shadow_access" >> /etc/audit/rules.d/99-shadow.rules
service auditd restart

6. Long‑Term Remediation & Monitoring
AREA	ACTION
Kernel Hardening	Enable module signing; restrict insmod to signed modules only.
Pod Security	Enforce PodSecurityPolicy or OPA Gatekeeper rules that deny host access unless explicitly approved.
Audit Logging	Centralize auditd logs to a secure, tamper‑evident SIEM; enable real‑time alerts for syscall=313 and openat /etc/shadow.
C2 Detection	Deploy Falco or Sysdig to flag outbound connections from cron jobs to unknown IPs.
RBAC Review	Periodically audit ServiceAccounts for cluster‑admin privileges; enforce least privilege.
Incident Response Playbook	Update playbooks to include kernel module removal, node quarantine, and secret rotation as first‑line actions.
7. Conclusion

The evidence conclusively demonstrates a multi‑stage compromise confined to k8s-worker-node-01. The attacker achieved full cluster control, installed a stealth kernel rootkit, harvested credentials, and established persistent reverse‑shell access. Immediate isolation, kernel module removal, RBAC rollback, secret rotation, and cron cleanup are mandatory to contain the threat. Enhanced monitoring and hardening will prevent recurrence and enable rapid detection of similar future attacks.
